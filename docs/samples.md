# Sample PSDs

Six deterministic PSDs live under `Tests/Sample/`, regenerated by
`Tests/Sample/generate_samples.py` (uses `psd-tools` + Pillow). They exercise
the full PSD2UMG pipeline through Automation Spec tests.

| File | Canvas | Layers | What it tests |
|---|---|---|---|
| `Simple.psd` | 1920×1080 | 3 (Background, Logo, Footer) | Basic Image widget generation, 9-grid anchor inference |
| `Nested.psd` | 1920×1080 | 3 (HUD_Score, HUD_Time, Menu_Buttons_Play) | Layer-name hierarchy (group nesting deferred to follow-up) |
| `Buttons.psd` | 1920×1080 | 3 (PlayBtn#button_normal / _hovered / _pressed) | Same-name button-state aggregation into one `UButton` with three brushes |
| `NineSlice.psd` | 1920×1080 | 1 (Panel#9slice(8,8,8,8)) | `#9slice` tag → `FSlateBrush.Margin` + `DrawAs=Box` |
| `LinkedPsd.psd` | 1920×1080 | 1 (Avatar#linkedpsd(Avatar.psd)) | `#linkedpsd` recursive import → child `WBP_Avatar` |
| `Avatar.psd` | 256×256 | 1 (Body) | Target of `LinkedPsd.psd`'s reference |

Each `.psd` ships with `<Name>.expected.json` — a snapshot of the output
`FPsdReader::Read` produces. `PsdReader.spec.cpp` asserts the live output
matches the snapshot.

`Buttons.psd` also has a `Buttons.psd.json` sidecar used by
`SidecarLoader.spec.cpp` and the Factory test (to verify
`commonButtonStyle` flows through to `FWidgetSpec::StyleAssetRef`).

## Regenerating

If a sample PSD's layer layout intentionally changes:

```bash
cd Tests/Sample
python generate_samples.py
```

Then update the snapshots by toggling `PSD2UMG_REGENERATE_SNAPSHOTS` in
`Source/PSD2UMGTests/Private/Spec/PsdReader.spec.cpp`:

1. Set `#define PSD2UMG_REGENERATE_SNAPSHOTS 1`
2. Rebuild, run `Automation RunTests PSD2UMG.PsdReader` (writes new `.expected.json`)
3. Set `#define PSD2UMG_REGENERATE_SNAPSHOTS 0`
4. Rebuild, run again to confirm assertion-mode passes
5. Commit
